# VeriSketch project guidance

This workspace is a Next.js + TypeScript app for the VeriSketch project.

## Project purpose
VeriSketch generates verified, hand-drawn style diagrams from source text while grounding every claim in the original source material. The product is designed for students and self-learners who need revision diagrams without hallucinated or unverified relationships.

## Core architecture
- Next.js App Router project using TypeScript.
- Frontend and backend coexist in the same app.
- Gemini API is the LLM provider, accessed only from server-side code.
- All agent calls should be server-side in app/api routes or backend utilities.
- The app uses React Query for async server state and Zustand for client UI state.
- Excalidraw is used for editable, hand-drawn-style diagram rendering.

## Main folders
- app/ — routes, pages, API handlers
- components/ — UI building blocks for pipeline, canvas, eval table
- store/ — Zustand state
- queries/ — React Query hooks
- lib/ — all llm/provider, agents, skills, render adapters
- baseline/ — single-prompt baseline comparison implementation
- eval/ — evaluation fixtures, scoring, run harness
- docs/ — README and changelog

## Important implementation rules
1. Do not expose Gemini API keys in browser code.
2. Keep model/provider calls behind lib/llm/provider.ts.
3. Every claim node/edge should retain source_sentence grounding.
4. Verification and patch loops happen server-side.
5. Use responseSchema constrained JSON where structured LLM output is required.
6. Dark-mode-first UI polish is expected for the product experience.
7. Prefer deterministic skills for rule-based logic, and reserve LLM calls for true judgment work.

## Current scaffold status
This repo is intentionally scaffolded but not yet implemented with real agent logic. The goal is to complete the backend architecture and evaluation flow before adding the final production logic.
